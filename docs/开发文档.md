# GoSlow 开发文档

> 一个"效率很低"的单词学习 App。不为了背而背,把单词学习嫁接进真实的阅读、观影、听歌场景。
> 状态:M5 内容扩展进行中（epub/srt/lrc 解析器 + 结构化阅读器完成） · 2026-08-31 · 完全重写(不沿用旧项目 `cursor_wordsmemory-cursor` 的代码与逻辑)

---

## 1. 项目概览

| 项 | 内容 |
| --- | --- |
| 项目名 | GoSlow(可改) |
| 一句话定位 | 把考纲词汇"镶嵌"进你真实读的书、看的电影、听的歌里,遇到即学,看见就认识 |
| 平台 | Android + iOS(Flutter) |
| 词库 | ECDICT 全量考纲词,离线内置,无 AI |
| 数据 | 纯本地存储,无账号、无云同步 |
| 与旧项目关系 | 完全重写,不参考旧项目任何代码、数据结构、算法逻辑 |

### 1.1 核心理念(为什么做这个产品)

- **学习英语最好的方式是在环境里获得**:去对话、去看当地电影、去听音乐,慢慢浸染。单词是附带的收获,不是目的。
- **最快的应试方式是肌肉记忆**:看到一个词就"认识",像外国人看待 `got` / `get` 一样——它们就是两个独立的词,不需要在心里过一遍时态推导。**不教语法,不做词性分析,不拆时态**。
- **单背单词没有反馈**:"我今天背了 200 个,然后呢?"——没有内容、没有收获感。但读一本书、听一首歌、看一部电影是有内容的。**把单词学习附带上内容和收获,一个时间干两件事**,用户才会觉得时间有价值。
- **给过程中的人用,不是给结果的人用**:不追求每天打卡数量,允许慢、允许低效,重点是"在路上"。

### 1.2 三个设计原则

1. **识别优先(Recognition First)**:所有学习动作都围绕"看见 → 秒认"。没有词根拆解、没有语法讲解、没有时态表格。
2. **内容嫁接(Content-Anchored)**:词永远来自一段真实的上下文(书/电影/歌),永远可以回看它出现的句子。
3. **反馈来自收获(Outcome-Driven Feedback)**:正反馈来自"读完了一本书"、"认识了 500 个词"、"本周听了 3 小时英语歌",而不是"点了 200 下卡片"。

## 2. 产品定位与核心流程

### 2.1 用户旅程

**旅程 A:内容 → 高亮 → 点词学习(核心)**
用户粘贴一段文本 / 导入一本书 / 导入一部电影的字幕 / 导入一首歌的歌词 → App 自动把其中所有"当前考纲"的词高亮 → 用户像正常阅读一样读/看/听 → 遇到高亮词点一下看释义 → 收藏 / 加入学习队列。

**旅程 B:识别式闪卡(学习与"快速筛选"合并)**
打开闪卡 → 看到单词 → 秒认 → 自评「认识 / 模糊 / 不认识」→ 认识的进入下一张,模糊/不认识的翻面看释义 → 按掌握度安排下次出现。

**旅程 C:收藏夹**
把想重点照顾的词(备考高频、总记不住的)收藏起来,随时翻看。

**旅程 D:收获感**
设置页看总览数据 → 详细统计页看趋势 → 达成里程碑时出现庆祝页 → 每周/每月收到沉浸总结和周报。

### 2.2 主界面结构(Tab 级)

```
底部 Tab
├─ 📚 内容(导入内容列表 + 阅读/播放界面)
├─ 🃏 闪卡(识别式学习)
├─ ⭐ 收藏(收藏夹)
└─ ⚙️ 设置(总览数据 + 详细统计 + 周报/月报 + 关于)
```

> 注意:不设独立的"词库浏览"主入口(词根词缀模式已废弃)。词库只在闪卡和统计中被间接接触,保持产品聚焦"内容"而非"词表"。

## 3. 功能需求

### 3.1 内容导入与高亮(核心模块)

#### 导入方式(P1 全做)
| 方式 | 说明 |
| --- | --- |
| 粘贴文本 | 直接粘贴英文段落/文章,立即高亮 |
| 导入 .txt / .md | 读取本地文本文件,按段落/章节组织 |
| 导入 .epub | 解析电子书,保留章节目录、段落结构,支持翻页阅读 |
| 导入 .srt / .ass | 字幕文件,按时间轴组织为"字幕行",配合本地视频播放时逐行展示(P2 联播,先能做字幕文本高亮阅读) |
| 导入 .lrc | 歌词文件,按时间轴组织,配合本地音乐播放时逐行展示(P2 联播,先能做歌词文本高亮阅读) |

#### 高亮规则
- 使用 ECDICT 词库(见 §5)做**词形还原后匹配**:文本中的 `got / going / better / teeth` 等变形词,通过 `exchange` / lemma 映射回原型,判断原型是否属于当前考纲。
- 高亮对象:属于**当前选中考纲**的词(见 §3.2 考纲切换)。
- 高亮样式:默认蓝色高亮 + 加粗(**单一颜色**,只高亮当前考纲的词);设置里可切换为**多色模式**(同时高亮所有考纲词,用不同颜色区分考纲)。两种模式可切换,见 §3.9。
- 词组支持:优先最长匹配(`give up` 优先于 `give` + `up`),ECDICT 中存在的词组词条优先命中。
- 性能:整本书/整部字幕一次性高亮需要可接受耗时(秒级),采用预构建内存索引(见 §7)。

#### 阅读界面(内容查看器)
- 纯文本/电子书:段落阅读、滚动、章节目录、阅读进度记录。
- 字幕/歌词:按行浏览,展示关联文件(视频/音频)的时间轴;P2 支持与本地播放器联动逐行滚动。
- 任意英文文本渲染为**可点击单词流**:点词弹出释义卡片(见 3.3)。
- 阅读时长统计(计入"沉浸时长")。

### 3.2 考纲切换(全局维度)

- 设置里可切换当前考纲:高考 / 四级 / 六级 / 考研 / 雅思 / 托福 / GRE / 中考 / 全部。
- 高亮、统计、闪卡均基于"当前考纲"过滤。
- 一个词可能同时属于多个考纲,数据层保留全部标签,展示层按当前考纲过滤。

### 3.3 点击高亮词 → 释义卡片(动作面板)

点词后底部弹出卡片,包含:

| 内容/动作 | 说明 |
| --- | --- |
| 释义 | 中文释义 + 英文释义 + 音标 + 词性 |
| 发音 | 本地 TTS 朗读单词 |
| 上下文 | 显示该词在当前位置所在的原句(回到语境) |
| 收藏 ⭐ | 加入收藏夹 |
| 加入学习队列 | 进入闪卡待学列表 |
| 标记"已认识" | 直接从高亮中移除该词(以后不再标亮) |

> 说明:原规划中的"整句翻译"已确认**不做**。理解句意靠:逐词查询 + 上下文原句回看 + 沉浸内容本身的连贯性(这正是"肌肉记忆/内容嫁接"理念——不依赖逐句翻译,而是在语境中反复遇见)。

### 3.4 识别式闪卡(学习 + 快速筛选合并)

这是唯一的主动学习模式,替代旧项目"学习/复习/快速筛选/随机问"所有模式。

**卡片来源（双入口，顶部 SegmentedButton 切换）**
1. **内容词**：内容中点词"加入学习队列"的词（`word_queue`）；
2. **考纲词**：当前考纲的全部词汇（跳过已认识；新词按词频/字母/随机排序，默认词频高频优先）；
3. （规划）高亮内容中未处理的词自动入队（设置开关，M4 评估）。

**卡片流程(单卡)**
```
正面:单词 + 音标(无释义)
  ↓ 用户自评
  ├─ 认识 ✅ → 掌握度+1,进入下一张
  ├─ 模糊 😐 → 翻面看释义,进入"待复习"池
  └─ 不认识 ❌ → 翻面看释义,进入"待复习"池
```

**设计要点**
- **不做任何语法/时态/词根讲解**。翻面只展示释义(中英) + 例句(如果有上下文则回看原句)。
- 掌握度用**简单状态机**,不引入 FSRS(见 §8)。
- 每天进入闪卡时,优先复习"模糊/不认识"的旧卡,再学新卡。
- 一个 session 结束(可自定,如 10/20 张)进入结算页(轻量庆祝,见 3.6)。

### 3.5 收藏夹

- 手动收藏的词集合,按收藏时间倒序。
- 每条显示:单词、释义、收藏时的来源(哪本书/哪部电影/哪首歌 + 原句)。
- 支持:移除收藏、从收藏加入闪卡队列、按考纲筛选、搜索。
- 统计中"收藏数"作为次要指标展示。

### 3.6 庆祝页(里程碑)

触发时机(全部保留):
1. **认识词数里程碑**:累计认识词数达到 100 / 500 / 1000 / 2000 / 3000 / 5000 …
2. **内容完成结算**:读完一本书 / 一部电影字幕 / 一首歌,结算该内容内遇到并处理的词(统计其中新认识的词、模糊词)。
3. **周/月目标达成**:达成用户自己设定的每周目标(可设定"本周要读完 1 本书"或"本周要认识 50 个词"等)。

庆祝页内容:大标题 + 达成数据 + 一句内容相关的收获总结(如"你读完了《XXX》,从中认识了 37 个新词")+ 可分享卡片。

### 3.7 统计:设置页总览 + 详细统计页

**总览(设置页顶部)**
- 累计认识词数(当前考纲)
- 累计沉浸时长(阅读/观影/听歌总分钟数)
- 语境中遇到并处理过的生词数
- 连续使用天数 / 周目标进度环

**详细统计页**
- 认识词数、沉浸时长、遇到生词数三者的趋势图(日/周)
- **掌握度曲线**:认识率随时间的变化(已处理词中"认识"占比)
- 每日活跃时间分布(可选)
- 当前考纲内词汇掌握分布:认识 / 模糊 / 不认识 / 未处理的数量

### 3.8 周报 / 月报

- 每周一 / 每月 1 日自动生成上一周期报告(也可随时手动查看历史)。
- 内容:
  - **学习量总结**:新认识词数、复习词数、累计认识词数;
  - **沉浸内容总结**:读了哪些书、看了哪些电影、听了哪些歌,各自的沉浸时长;
  - **困难生词回顾**:本周最常遇到却仍标记"模糊/不认识"的词清单(带来源原句)。
- 周报用一张可分享的卡片呈现,点击进入明细。

### 3.9 设置

- 当前考纲切换
- 高亮样式:高亮颜色、是否加粗、是否显示音标;**单一颜色模式(只高亮当前考纲)/ 多色模式(区分考纲)切换**
- 闪卡设置(每轮张数、新词自动入库开关、发音开关)
- 周目标设定
- 统计入口(总览 + 详细统计 + 周报/月报)
- 数据管理:导出全部学习数据(JSON/SQLite 备份文件)、导入恢复、清空数据
- 关于

## 4. 词库数据设计(ECDICT → SQLite)

### 4.1 数据来源
`/Users/jinfeiqing/Downloads/ECDICT-master/ecdict.csv`(约 70MB,约 76 万词条),附带 `lemma.en.txt`(词形还原映射,首选)与 `exchange` 字段(次选)。

### 4.2 表结构

```sql
-- 词条主表(仅保留考纲相关 + 展示需要的字段,缩减体积)
CREATE TABLE words (
  id          INTEGER PRIMARY KEY,
  word        TEXT NOT NULL UNIQUE,     -- 词条原型
  phonetic    TEXT,
  translation TEXT,                     -- 中文释义(多行)
  definition  TEXT,                     -- 英文释义(多行)
  pos         TEXT,                     -- 词性
  collins     INTEGER,                  -- 柯林斯星级
  oxford      INTEGER,                  -- 是否牛津3000
  bnc         INTEGER,                  -- BNC 词频
  frq         INTEGER,                  -- 当代词频
  exchange    TEXT                      -- 变形信息(原始字段)
);

-- 考纲标签(word 可属于多个考纲)
CREATE TABLE word_tags (
  word_id INTEGER REFERENCES words(id),
  tag     TEXT,                         -- zk/gk/cet4/cet6/ky/ielts/toefl/gre
  PRIMARY KEY (word_id, tag)
);

-- 词形还原映射(从变形词 → 原型),来源 lemma.en.txt + exchange 反向
CREATE TABLE lemma_map (
  inflected TEXT PRIMARY KEY,           -- got → get 的 got
  lemma     TEXT NOT NULL               -- 原型 get
);

-- 词组词条单独标记,用于最长匹配优先
CREATE INDEX idx_words_word ON words(word);
CREATE INDEX idx_lemma_map_inflected ON lemma_map(inflected);
```

### 4.3 生成流程(开发期脚本,不在 App 内)
1. 解析 `ecdict.csv`,筛选出**至少带一个考纲 tag**(zk/gk/cet4/cet6/ky/ielts/toefl/gre)的词条 + 少量常用词(便于释义展示)。
2. 拆出 `word_tags`。
3. 用 `lemma.en.txt` 构建 `inflected → lemma` 映射;对 lemma 不在 ECDICT 里的词,尝试用 `exchange` 字段反向推导补全。
4. 生成 `assets/dict.db`(SQLite),App 首次启动复制到应用目录,离线查询。

### 4.4 体积与性能
- 目标:内置词库 ≤ 50MB(仅考纲词,词条约 1.5 万 ~ 3 万条,远小于全量 76 万)。
- 高亮匹配用**内存哈希索引**(启动时把 words + lemma_map 载入内存),保证整本书秒级高亮。

## 5. 高亮引擎技术设计

```
输入:英文文本(整段 / 整本书 / 字幕 / 歌词)
步骤:
1. 预分词:按非字母数字字符切分,保留每个 token 的起止位置(用于点词回定位)。
2. 规范化:转小写,去标点。
3. 匹配:先查 words(原型命中);
   未命中 → 查 lemma_map(inflected → lemma)再查 words;
   仍无 → 非考纲词,不高亮。
4. 词组最长匹配:对相邻 token 尝试组合(2~3 词),优先命中词组词条。
5. 输出:高亮区间列表 + 每个高亮词的词条 id + 所在原句偏移。
```

- 点词定位:维护 `token 起始偏移 → 词条` 映射,点击时反查。
- 高亮存储不落库(文本是可再生成的),只记录每个内容的"处理进度"。

## 6. 掌握度模型（FSRS v4 间隔调度 + 事件溯源）

```
状态:未处理 → 学习中 → 认识 ✅ / 模糊 😐 / 不认识 ❌ → (按 S 排期,到期自动回来)
```

M3.5 起，掌握度由 **FSRS v4** 驱动（移植自旧项目 `cursor_wordsmemory-cursor` 的状态机结构，
修正了其两处数值缺陷，见 `lib/data/srs/fsrs_calculator.dart` 头部注释）：

| 字段 | 说明 |
| --- | --- |
| status | `unknown` / `learning` / `familiar` / `known`（由 SRS 状态派生，UI 语义不变） |
| stability S | 稳定性（天）。下次复习间隔 = S 天；答对增长、遗忘按 S_forget 衰减 |
| difficulty D | 难度（1-10，随评级演化，持久化） |
| retrievability R | 可提取性（0-1），`R(t,S)=1/(1+t/(9S))` |
| next_review_at | 下次复习时间（到期即进入复习队列） |
| fail_count | 累计遗忘次数 |
| correct/wrong/consecutive | 计数仅用于统计展示，不参与调度 |

**评级映射**：认识 → Good(3) · 模糊 → Hard(2) · 不认识 → Again(1)。

- **事件溯源**：每次自评落一条 `review_events`（操作前快照 + 操作后结果）。
  统计、撤销、未来换算法重放全部从事件表推导。
- 闪卡排队：FSRS 到期卡（`next_review_at <= now`）优先，known 且未到期的跳过，
  known 但**已到期**的低频抽查自动回来（对应"认识过的词也要低频复习"）。
- 统计口径（`StatsRepository.compute`，公式沿用旧项目）：
  - **成熟词** = status=known 且 R≥0.9；**成熟转化率** = 成熟词数 / 累计自评次数；
  - **成熟词汇失忆率** = 成熟词失忆事件数 / 成熟词数（Review 状态下 R<0.5 时仍 Again）；
  - **积压量** = 此刻已到期未复习词数；**掌握度曲线** = 每天认识率采样。
